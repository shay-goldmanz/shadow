A five-screen welcome carousel explaining features nobody asked about
is not onboarding; it is a toll booth. The best onboarding gets a new
user to one real, personally meaningful result as fast as possible and
explains everything else exactly when it becomes relevant, never
before.

Ask what the smallest real outcome is — one message sent, one project
created, one teammate invited — and design every step as friction
against reaching it. Any screen that does not either collect
information required for that outcome or remove a blocker to it should
be cut, not deferred to "step 2."

Warmth comes from specificity, not decoration. "Welcome, Priya" reads
warmer than a full-bleed illustration of a person waving. A setup
wizard that pre-fills a sensible default and lets the user accept it
with one click feels more considerate than one that presents every
option up front and calls that "flexibility."

Sequence, do not parallelize, unavoidable setup steps — asking for
five permissions on one screen produces five reasons to bounce. Ask
for the one permission the very next screen needs, when the user can
see why it's being asked.
